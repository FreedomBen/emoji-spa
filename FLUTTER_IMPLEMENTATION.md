## 2. State Management Architecture

### 2.1 Approach

Use a single `ChangeNotifier` with `Provider`. The app has a flat state model well-suited to this simple approach.

### 2.2 Core State Shape

```
EmojiAppState:
  allCategories: Map<String, List<String>>    # category name → emoji list
  metadataByEmoji: Map<String, EmojiMetadata> # emoji → {name, keywords}
  emojiUsage: Map<String, UsageRecord>        # emoji → {count, lastUsed}
  pinnedEmojis: Set<String>
  hiddenEmojis: Set<String>
  searchQuery: String
  selectedCategory: String                    # "all" or category name or special
  groupByCategory: bool
  showFrequentlyUsed: bool
  showRecentlyUsed: bool
  themePreference: ThemePreference            # system / light / dark
```

### 2.3 Persistence Strategy

Throttled writes to storage:
- On any state mutation that affects persisted data, schedule a save after 1000ms.
- If a save is already scheduled, skip (do not reset the timer). When the timer fires, persist the latest state. This means the first mutation in a window determines *when* the save runs, but the save itself captures whatever state exists at that moment.
- Use `shared_preferences` for persistence on both Linux desktop and web.

### 2.4 Storage Keys & Schema

Storage keys and JSON schema:

- `emojiUsage.v1` → JSON with `{version, items, pinned, hidden, groupByCategory, showFrequentlyUsed, showRecentlyUsed}`
- `emojiThemePreference.v1` → String: `"system"`, `"light"`, or `"dark"`

## 3. Emoji Generation & Detection

### 3.1 Unicode Iteration

Implement the emoji generation algorithm in Dart. This logic runs only in the `tool/generate_emoji_categories.dart` CLI script (§3.3) — the app itself loads the pre-computed result from a bundled JSON asset:

1. Iterate code points 0 through 0x10FFFF.
2. Convert each to a `String` via `String.fromCharCode()` (Dart handles code points above U+FFFF natively — no surrogate pair handling needed).
3. **Dual-gate emoji detection** (must pass both checks):
   a. Test with Dart's RegExp: `RegExp(r'\p{Emoji}', unicode: true)`. If the regex doesn't match, reject. Dart supports Unicode property escapes natively.
   b. Test against heuristic code point ranges: 0x1F300–0x1FFFF, 0x2600–0x26FF, 0x2700–0x27BF. If the code point is outside all of these ranges, reject. This prevents digits, `#`, `*`, and other characters that match `\p{Emoji}` but are not visual emoji from being included.
4. Skip variation selectors (U+FE0F) and combining enclosing keycap (U+20E3). This skip happens inside the iteration loop of `generateEmojiByCategoryInternal()`, not in the `isEmoji()` function itself.
5. Categorize via `getCategory(codePoint)` using the same code point ranges.

### 3.2 Category Mapping

Define 15 categories with their code point ranges (order matches `getCategory()` evaluation order):

- Smileys & Emotion (0x1F600–0x1F64F)
- People & Body (0x1F466–0x1F487)
- Animals & Nature (0x1F400–0x1F4D3)
- Food & Drink (0x1F347–0x1F37F)
- Travel & Places (0x1F3E0–0x1F3FF)
- Transport & Map (0x1F680–0x1F6FF)
- Alchemical Symbols (0x1F700–0x1F77F)
- Geometric Symbols (0x1F780–0x1F7FF)
- Supplemental Arrows (0x1F800–0x1F8FF)
- Supplemental Symbols & Pictographs (0x1F900–0x1F9FF)
- Symbols & Pictographs Extended-A (0x1FA00–0x1FAFF)
- Misc Symbols (0x2600–0x26FF)
- Dingbats (0x2700–0x27BF)
- Regional Indicators (0x1F1E6–0x1F1FF)
- Other Emoji (fallback)

### 3.3 Build-Time Pre-computation

The category map is deterministic per Unicode version, so generate it once at build time rather than at runtime:

1. Write a standalone Dart CLI script (`tool/generate_emoji_categories.dart`) that runs the full 0–0x10FFFF iteration, categorization, and deduplication.
2. Output the result as `assets/emoji-categories.json` — a JSON map of `{ categoryName: [emoji, ...], ... }`. Categories are sorted alphabetically; emojis within each category are sorted by code point and deduplicated.
3. Add a Makefile target (`flutter-generate-emoji`) that runs this script. Wire it into `flutter-build-linux` and `flutter-build-web` as a prerequisite.
4. At app startup, load the pre-computed JSON via `rootBundle.loadString()` instead of running the generation algorithm. This eliminates all startup cost and avoids needing an isolate. If the asset is missing or fails to parse, fail hard with a clear error — this is a required build artifact, not an optional optimization.
5. The generation script itself must still run off the main thread in CI / dev machines, but since it's a CLI tool that's fine — no isolate plumbing needed in the app.

The `tool/` script reuses the same `emoji_generator.dart` logic (imported as a library), so there is a single source of truth for the algorithm. Re-run `make flutter-generate-emoji` whenever the Unicode version or category ranges change.

### 3.4 Category Keywords

Define a `CATEGORY_KEYWORDS` map (category name → search keyword list). Used during search to match on category names. See `frontend/app.js` for the reference keyword lists.

## 4. Metadata System

### 4.1 Base Metadata

Include the 93 base emoji metadata entries as either:
- A Dart file with a `Map<String, EmojiMetadata>` literal, or
- A JSON asset loaded at startup.

Dart file is simpler and avoids async loading.

### 4.2 CLDR Overlay

Load `assets/emoji-cldr.json` via `rootBundle.loadString()` at startup. Parse and merge:
- CLDR name overrides base name (only if base doesn't already have one).
- Keywords are unioned (deduplicated).

### 4.3 Slack Keywords

Load `assets/emoji-slack.json` similarly. Merge keywords into `metadataByEmoji`.

### 4.4 Initialization Order

Initialization flow:

1. Apply theme from storage (synchronous — show themed shell immediately).
2. Load pre-computed emoji categories (from bundled `emoji-categories.json`).
3. Load CLDR metadata (from bundled `emoji-cldr.json`).
4. Load Slack metadata (from bundled `emoji-slack.json`).
5. Load usage data from storage.
6. Merge metadata into `metadataByEmoji`.
7. Build category dropdown options.
8. Render initial view.

Steps 2–5 are all async reads and can run concurrently with `Future.wait()`. Show a loading indicator until all are complete.

## 5. Search & Filtering

### 5.1 Tokenization

Split query by whitespace, filter empty strings. Each token must match at least one searchable field (AND logic across tokens).

### 5.2 Searchable Fields Per Emoji

For each emoji, check tokens against (all case-insensitive substring matching):
1. The emoji character itself.
2. Category name.
3. Category keywords (from `CATEGORY_KEYWORDS`).
4. Metadata name.
5. Metadata keywords.

### 5.3 Filter Pipeline (`applyFiltersAndRender` equivalent)

1. Start with `allCategories`.
2. If a specific category is selected, narrow to that category.
3. For each category, filter emojis by token matching.
4. Exclude hidden emojis (unless viewing "Hidden" section).
5. Handle special sections:
   - **Pinned** — pinned emojis matching current search.
   - **Frequently Used** — emojis with `count >= FREQUENT_MIN_COUNT` (2), sorted by count desc then lastUsed desc, limited to `FREQUENT_LIMIT` (50).
   - **Recently Used** — sorted by lastUsed desc, limited to `RECENT_LIMIT` (50), excluding emojis already in Frequently Used.
   - **Hidden** — hidden emojis matching current search (collapsible).
6. Optionally group by category or show flat list.
7. Reset scroll position to top when the selected category changes.

### 5.4 Hidden Emoji Hint

When search matches only hidden emojis and no visible results, show a hint message: "Some hidden emoji match your search. Try the Hidden section."

## 6. UI Components

### 6.1 App Shell

- `Scaffold` with a sticky header (search bar + category dropdown + "Group by Category" checkbox).
- Scrollable body with category sections.
- Settings panel as a modal dialog or drawer.

### 6.2 Search Bar

- `TextField` with `InputDecoration` matching the current styling.
- `Ctrl+S` / `Cmd+S` global shortcut: focus search, select all text.
- `Escape`: clear search text, refocus search.
- `input` event equivalent: listen to `TextEditingController` changes, trigger filter.

### 6.3 Category Dropdown

- `DropdownButton<String>` or equivalent.
- Options rebuilt on every filter pass (not just on init) — the available special sections change as usage data and pinned/hidden state change.
- Options built dynamically:
  1. "All categories" (always first).
  2. "Pinned" (if any pinned emojis exist).
  3. "Frequently Used" (if enabled and has emojis meeting threshold).
  4. "Recently Used" (if enabled and has recent emojis).
  5. Base categories in alphabetical order.
  6. "Hidden" (if any hidden emojis exist, always last).
- If the currently selected category is removed from the dropdown (e.g., all pinned emojis are unpinned while viewing "Pinned"), fall back to "All categories".

### 6.4 Emoji Grid

- Use `GridView.builder` with `SliverGridDelegateWithMaxCrossAxisExtent`. The CSS uses `minmax(36px, 1fr)` with a `0.25rem` (4px) gap — the exact `maxCrossAxisExtent` value will need visual tuning during implementation to achieve parity (start around 40–44 and adjust).
- Each item is an `EmojiButton` widget.
- Wrap in category sections: each section has a header (`Text` with category name and count) followed by its grid.
- When `groupByCategory` is false, render a single flat grid.

### 6.5 Emoji Button

- `GestureDetector` + `MouseRegion` wrapping a `Text` widget with the emoji character.
- **Click/tap**: copy emoji to clipboard, record usage, show status feedback.
- **Right-click** (desktop) / **long-press** (touch): show context menu.
- **Hover**: subtle background change + slight upward translate (match CSS `translateY(-1px)`).
- **Focus ring**: 2px accent-colored outline on keyboard focus.
- Font size ~1.4rem equivalent.

### 6.6 Context Menu

- Use `showMenu()` (Flutter's built-in popup menu) or a custom positioned overlay.
- Three actions:
  - Pin / Unpin (label toggles based on current state).
  - Hide / Unhide (label toggles).
  - Reset usage.
- Position clamped to viewport bounds with 8px minimum margin.
- Dismiss on click outside, window resize, or Escape.

### 6.7 Settings Panel

Implement as a modal dialog (`showDialog` or side sheet). Sections:

1. **Theme selection** — Radio group: System / Light / Dark. Changes apply immediately and persist.
2. **Reset all usage** — Danger button. Confirm with `showDialog` confirmation (replacing `window.confirm()`) with message: "Reset all usage data, pinned emoji, and hidden emoji?". Clears all usage data, pinned, hidden.
3. **Usage section toggles** — Two checkboxes: "Show Frequently Used", "Show Recently Used". Changes persist and trigger re-render.
4. **Usage table** — `DataTable` or `ListView` showing: Emoji | Name | Category | Count. Sorted by count descending.
5. **Keyboard shortcuts reference** — List of shortcuts with descriptions.

### 6.8 Keyboard Tooltip

When navigating emojis with the keyboard, show a tooltip below the focused button after a 1-second delay:
- Content: `emoji — Category Name (used N times)`.
- Implemented as an `OverlayEntry` positioned relative to the focused widget.
- Hidden on blur, Escape, or mouse interaction.

### 6.9 Hidden Section

- Render as an `ExpansionTile` or custom collapsible (matching the HTML `<details>/<summary>` pattern).
- Summary shows "Hidden (count)".
- Contains an emoji grid of hidden emojis matching the current search.

### 6.10 Status Bar / Feedback

- Show a brief status message when an emoji is copied (e.g., "Copied 😀").
- Use an inline status text widget in the header area (matching the current `#status` element), not a `SnackBar`. The feedback should appear near the action, not at the bottom of the screen.

## 7. Keyboard Navigation

### 7.1 Focus System

Flutter has a built-in focus system (`FocusNode`, `FocusTraversalGroup`). Use it with custom traversal for grid navigation.

### 7.2 Grid Navigation

- **Arrow keys (← → ↑ ↓)**: Move focus within the emoji grid. Calculate grid columns from the viewport width to determine row wrapping. Left/Right move linearly; Up/Down jump by column count.
- **Home / End**: Jump to first / last emoji in the current grid.
- **Up on first row**: Move focus back to search field.
- **Down from search field** (caret at end): Move focus to first visible emoji.

### 7.3 Type-to-Search

When an emoji button is focused and the user types a printable character (no Ctrl/Alt/Meta modifier):
- Append the character to the search query.
- Re-filter results.
- Do NOT intercept if the focused widget is the search field, category dropdown, or any text input.

Backspace while emoji focused: remove last character from search query.

### 7.4 Global Shortcuts

| Shortcut | Action |
|----------|--------|
| `Ctrl+S` / `Cmd+S` | Focus search field, select all text |
| `Escape` | Close overlays, clear search, focus search |
| `Enter` / `Space` | Copy focused emoji |

Register via `Shortcuts` + `Actions` widgets at the app level, or `RawKeyboardListener` / `KeyboardListener`.

## 10. Platform-Specific Concerns

### 10.1 Linux Desktop

- **Window configuration**: Use `window_manager` package to set initial size 1000x800, title "Emoji Spa", resizable, no fullscreen. Match `tauri.conf.json` settings.
- **Close behavior**: The Tauri app has a `close_app_window` command. In Flutter, closing the window is the default behavior — no special handling needed unless we want Ctrl+W/Ctrl+Q shortcuts, which can be registered as global key handlers that call `window_manager`'s close/destroy.
- **Desktop icon**: Place icon PNGs in `linux/` directory and configure in `my_application.cc` or via `window_manager.setIcon()`.

### 10.2 Web

- **SPA routing**: Flutter web is a single-page app by default. No special routing config needed for the emoji picker (single screen).
- **Asset loading**: `rootBundle.loadString()` works for bundled JSON assets.
- **Persistence**: `shared_preferences` handles web storage transparently.
- **URL strategy**: Use hash URL strategy (default) since there's no server-side routing.

### 10.3 Emoji Font Rendering

Flutter on Linux renders text using Skia, which picks up system fonts. Emoji rendering depends on the user having a color emoji font installed (e.g., `Noto Color Emoji` ships with most distros but not all minimal installs). Strategy:

1. **Bundle `NotoColorEmoji.ttf`** in `assets/fonts/` (~10MB). Declare it in `pubspec.yaml` as a fallback font family.
2. **Prefer system fonts**: In the `TextStyle` for emoji text, set `fontFamilyFallback: ['Noto Color Emoji']` where the bundled font is registered under that family name. The system's own emoji font (if present and higher priority) will be used first; the bundled copy is the safety net.
3. **Web**: Browsers handle emoji fonts natively. Exclude `NotoColorEmoji.ttf` from web builds to avoid a ~10MB unnecessary download. Use conditional asset bundling in `pubspec.yaml` or a build-time step that strips the font from the web output.

This ensures every Linux user sees color emoji regardless of their distro's default font packages, without penalizing web users.

### 10.4 Font Size Mapping

Flutter uses logical pixels (1:1 with CSS pixels at 1x device pixel ratio). Mapping from the reference CSS:

| CSS | Flutter |
|-----|---------|
| `1rem` (16px) | `16.0` logical pixels |
| `1.4rem` (22.4px) — emoji button font | `22.0` logical pixels |
| `0.875rem` (14px) — small text | `14.0` logical pixels |
| `0.25rem` (4px) — grid gap / padding | `4.0` logical pixels |
| `0.375rem` (6px) — border radius | `6.0` logical pixels |

Round to nearest whole pixel where sub-pixel differences are invisible. Verify visual parity by comparing screenshots of both apps side-by-side.

### 10.5 Shared Code

All business logic (emoji generation, search, usage tracking, metadata merging) lives in platform-agnostic Dart. Only the storage backend and window management differ by platform, abstracted behind service interfaces.

## 15. Resolved Decisions

1. **State management**: Use `provider` package with `ChangeNotifier`. Simple, sufficient for this app's flat state model.

2. **Emoji font rendering**: Bundle `NotoColorEmoji.ttf` as a fallback font. System emoji fonts take priority when available; the bundled copy is a safety net for minimal Linux installs. See §10.3 for details.

3. **Emoji generation at build time**: Pre-compute the emoji category map via a `tool/generate_emoji_categories.dart` CLI script. The app loads the result from a bundled JSON asset — no runtime Unicode iteration, no isolate needed. See §3.3 for details.

4. **Browser extensions**: Not targeted by the Flutter build. Flutter's web payload (~2MB+) is too heavy for extension popups.

5. **Accessibility**: Use Flutter's native `Semantics` widget tree for labeled emoji buttons, navigable regions, and keyboard-reachable controls.

6. **Font size mapping**: 1rem = 16 logical pixels. Emoji buttons at 1.4rem = 22 logical pixels. See §10.4 for the full mapping table.
